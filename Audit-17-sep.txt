## Executive conclusion

## 🔴 NOT SAFE FOR PRODUCTION

The application should **not go live in its current state**.

The most serious blockers are:

1. **Critical authorization gaps on administrative and data-mutating APIs**
2. **Hardcoded JWT/encryption fallback secrets**
3. **CSRF explicitly disabled in backend configuration**
4. **Database credentials and API secrets present in local environment files**

8. **12 npm dependency vulnerabilities, including a critical Next.js advisory**
9. **Production build failure due to `.next/trace` filesystem permissions**
10. **No demonstrated account deletion, privacy rights, retention, consent, or child-safety controls**

The codebase is a partially integrated LMS prototype with several fallback/demo paths still reachable from production-facing routes. It contains a useful feature set, but security boundaries and operational controls are not mature enough for public launch.

## Main data flows

### Authentication

- Frappe login creates a session identifier.
- Frontend stores `frappe_sid` in `localStorage`.
- The session ID is appended to query strings for Frappe calls.
- Next.js exchanges the session for a custom JWT.
- Custom JWT is HMAC-SHA256 signed using an environment value or fallback secret.

### Document ingestion

- User uploads PDF to Next.js.
- File is copied to Backblaze B2.
- Metadata is inserted into the database.
- Queue row is inserted.
- Python worker downloads the file, extracts text, generates embeddings, and writes vector chunks.
- SSE polls database status.

### AI/RAG

- User input is sent to Next.js.
- Embedding is generated using Gemini.
- Vector search is executed against database tables.
- Conversation history is loaded from Redis.
- Prompt, memory, and retrieved document chunks are sent to Gemini.
- Conversation data and token counters are written to Redis.

# 4. Findings register

## Critical findings

### F-001 — Unauthenticated administrative mutation APIs

- **Category:** Authorization / API security
- **Severity:** CRITICAL
- **Component:** Next.js API routes
- **Locations:**
  - `frontend/app/api/courses/route.js`
  - `frontend/app/api/courses/[id]/syllabus/route.js`
  - `frontend/app/api/assignments/route.js`
  - `frontend/app/api/quizzes/route.js`
  - `frontend/app/api/categories/route.js`
  - `frontend/app/api/admin/courses/import/route.js`
- **Evidence:** `POST`, `PUT`, and `DELETE` handlers do not authenticate the caller or verify an administrator role.
- **Problem:** Any network client able to reach the application may create, modify, replace, or delete course, syllabus, assignment, quiz, and category data.
- **Impact:** Complete content tampering, destructive deletion, unauthorized publishing, privilege abuse.
- **Likelihood:** High
- **Risk:** Critical
- **Recommended fix:** Centralize server-side authentication and authorization middleware. Require Frappe role verification or a server-side admin permission check for every administrative operation. Do not rely on UI route protection or local storage.
- **Complexity:** Medium
- **Pre-launch required:** YES

### F-002 — Unauthenticated progress and memory access

- **Category:** Authorization / Privacy
- **Severity:** CRITICAL
- **Locations:**
  - `frontend/app/api/progress/route.js`
  - `frontend/app/api/memory/route.js`
- **Evidence:** `progress` accepts caller-supplied `email`; no authentication is checked. The no-email branch enumerates all Redis keys matching `completed_lessons:*`. Memory operations accept caller-supplied `sessionId` and `userId`.
- **Problem:** A user can retrieve or overwrite another student’s progress and potentially access another user’s conversation memory.
- **Impact:** Cross-user disclosure, academic record manipulation, privacy violation.
- **Likelihood:** High
- **Recommended fix:** Derive user identity exclusively from the authenticated server session/JWT. Remove caller-controlled user identifiers from authorization decisions. Add object-level authorization tests.
- **Complexity:** Medium
- **Pre-launch required:** YES

### F-003 — Hardcoded authentication fallback secret

- **Category:** Authentication / Secrets
- **Severity:** CRITICAL
- **Locations:**
  - `frontend/lib/auth.js:25`
  - `frontend/app/api/auth/jwt/route.js:6`
  - `backend/init-render-web.sh:83`
  - `backend/init.sh:23`
  - `backend/patch_api.py:436`
- **Evidence:** Authentication falls back to a fixed secret when environment configuration is missing.
- **Problem:** Anyone knowing the source can forge valid JWTs. Misconfigured environments silently become forgeable.
- **Impact:** Account impersonation, tenant bypass, document access, administrator impersonation.
- **Likelihood:** High
- **Recommended fix:** Fail closed if the secret is missing. Use a single managed secret. Rotate the currently exposed value. Prefer Frappe/OIDC-signed tokens or asymmetric JWT validation. Validate issuer, audience, subject, expiration, not-before, and tenant claims.
- **Complexity:** Medium
- **Pre-launch required:** YES

### F-004 — Fixed production credentials

- **Category:** Authentication / Secrets
- **Severity:** CRITICAL
- **Locations:**
  - `backend/create_students.py:145-146`
  - `backend/create_students.py:173-174`
  - `backend/init-render-web.sh:152`
  - `backend/init.sh:196-197`
  - `frontend/app/login/page.jsx:97-104`
  - `frontend/app/login/page.jsx:415`
- **Evidence:** Administrator and student passwords are hardcoded and displayed in the login UI.
- **Problem:** All seeded users share predictable credentials. Startup scripts reset passwords on every deployment.
- **Impact:** Immediate unauthorized account access and administrator takeover.
- **Recommended fix:** Remove demo credentials and password display. Generate one-time bootstrap credentials through a secure secret manager. Require password reset on first login. Never reset production passwords during startup.
- **Complexity:** Low/Medium
- **Pre-launch required:** YES

### F-005 — CSRF protection disabled

- **Category:** Web security
- **Severity:** CRITICAL
- **Locations:**
  - `backend/init-render-web.sh:68`
  - `backend/init.sh:130`
- **Evidence:** `bench set-config -g ignore_csrf 1`
- **Problem:** Cookie-authenticated state-changing operations can be triggered cross-site.
- **Impact:** Unauthorized course modification, account actions, data changes, and potentially administrative actions.
- **Recommended fix:** Re-enable CSRF protection. Use same-site cookies where possible. For cross-site OAuth/session flows, implement explicit CSRF state validation and origin checks. Add CSRF tests for all cookie-authenticated mutations.
- **Complexity:** Medium
- **Pre-launch required:** YES

### F-006 — Real PII and user content committed in database dump

- **Category:** Privacy / Data protection / Secrets
- **Severity:** CRITICAL
- **Location:** `backup.sql`
- **Evidence:** Dump contains real-looking email addresses, phone numbers, locations, education and employment history, resumes, uploaded document content, and embeddings.
- **Problem:** The repository contains production-like personal data and potentially sensitive educational material.
- **Impact:** Privacy breach, regulatory exposure, unauthorized disclosure, accidental redistribution through source control.
- **Recommended fix:** Remove the dump from the repository and all history where applicable. Rotate credentials if dump access includes secrets. Purge or anonymize PII. Establish a sanitized fixture policy. Verify database dump access controls and encryption.
- **Complexity:** Medium/High
- **Pre-launch required:** YES

### F-007 — Secrets present in local environment files

- **Category:** Secrets management
- **Severity:** CRITICAL
- **Locations:**
  - `backend/.env`
  - `frontend/.env`
- **Evidence:** Files contain database credentials, Redis tokens, Gemini keys, OAuth client secret, internal service token, and encryption/JWT material. They are ignored by Git but present in the workspace.
- **Problem:** Ignoring a file does not protect secrets from local compromise, accidental packaging, logs, backups, or developer sharing.
- **Recommended fix:** Revoke and rotate all exposed values. Use a secret manager. Add pre-commit and CI secret scanning. Verify build artifacts do not contain secrets. Maintain only redacted `.env.example` files.
- **Complexity:** Low/Medium
- **Pre-launch required:** YES

## High findings

### F-008 — Session identifier stored in localStorage and query parameters

- **Category:** Session management
- **Severity:** HIGH
- **Locations:**
  - `frontend/lib/frappe.js:130-138`
  - `frontend/lib/frappe.js:161-169`
  - `frontend/lib/frappe.js:220-228`
  - `frontend/app/api/documents/status-stream/route.js:9`
- **Problem:** Session identifiers and JWTs can leak through XSS, browser history, proxy logs, analytics, referrers, screenshots, and server logs.
- **Fix:** Use Secure, HttpOnly, SameSite cookies. Never put credentials in URLs. Remove query-string token support from SSE.

### F-009 — Wildcard CORS and cross-site cookies

- **Category:** Web security
- **Severity:** HIGH
- **Locations:**
  - `backend/init-render-web.sh:67-68`
  - `backend/init-render-web.sh:84-85`
  - `backend/init.sh`
- **Problem:** CORS defaults to `*`, while cookies are configured with `SameSite=None`.
- **Fix:** Allow only explicit production origins. Use `Secure`, `HttpOnly`, and appropriate `SameSite`. Validate `Origin` for sensitive requests.

### F-010 — Missing authorization on API consumption endpoint

- **Category:** Authorization / Privacy
- **Severity:** HIGH
- **Location:** `frontend/app/api/admin/api-consumption/route.js`
- **Problem:** Anyone can retrieve token usage statistics, including per-user identifiers.
- **Fix:** Require an administrator role and return aggregated data where possible.

### F-011 — Unbounded AI endpoints and cost abuse

- **Category:** Abuse prevention / Cost
- **Severity:** HIGH
- **Locations:**
  - `frontend/app/api/gemini/route.js`
  - `frontend/app/api/gemini/stream/route.js`
  - `frontend/app/api/labs/tutor/route.js`
  - `frontend/app/api/youtube/chat/route.js`
  - `frontend/app/api/youtube/explain/route.js`
  - `frontend/app/api/generate-aptitude/route.js`
  - `frontend/app/api/viva-interview/route.js`
- **Problem:** Several AI routes do not authenticate users or enforce meaningful per-user, IP, token, concurrency, or cost limits.
- **Impact:** API-key abuse, denial of service, unexpected Gemini bills.
- **Fix:** Require authenticated identity, enforce request body size, input length, output-token ceilings, concurrency limits, per-user quotas, IP throttling, and global spend alerts.

### F-012 — File upload validation is insufficient

- **Category:** File security
- **Severity:** HIGH
- **Location:** `frontend/app/api/documents/upload/route.js:72-87`
- **Problem:** Validation relies on MIME type or filename suffix. PDF structure is not robustly validated, and the full multipart body is parsed before size enforcement.
- **Fix:** Enforce request/body limits at the reverse proxy and application server. Validate magic bytes, parse safely in a sandbox, reject encrypted/active-content PDFs where appropriate, sanitize metadata, and scan uploads. Use object-storage quarantine and lifecycle rules.

### F-013 — Document deletion is not transactionally consistent with B2

- **Category:** Reliability / Data lifecycle
- **Severity:** HIGH
- **Location:** `frontend/app/api/documents/delete/route.js`
- **Problem:** B2 deletion errors are logged and ignored, while database metadata is deleted.
- **Impact:** Orphaned personal files, retention failures, storage cost, inability to honor deletion requests.
- **Fix:** Use a deletion state machine/outbox job, retry object deletion, verify completion, and periodically reconcile database/object storage.

### F-014 — Worker startup can destroy the database

- **Category:** Reliability / Infrastructure
- **Severity:** HIGH
- **Location:** `backend/init-render-web.sh:134-156`
- **Problem:** If initialization checks fail, the script drops all database tables and creates a new site.
- **Impact:** Catastrophic production data loss caused by transient DB connectivity or schema-check failure.
- **Fix:** Never automatically wipe a production database. Separate initialization from deployment. Require an explicit, impossible-to-miss development-only flag for destructive resets.

### F-015 — No health/readiness distinction

- **Category:** SRE
- **Severity:** HIGH
- **Locations:**
  - `frontend/server-with-ws.js:101-104`
  - `frontend/voice-server.js:75-82`
- **Problem:** Health endpoints return `healthy` even when Gemini, Redis, database, worker, or storage dependencies may be unavailable.
- **Fix:** Add liveness and readiness endpoints with dependency checks, timeouts, and deployment integration.

### F-016 — No CI/CD security gates

- **Category:** DevSecOps
- **Severity:** HIGH
- **Evidence:** No `.github/workflows`, GitLab pipeline, Jenkinsfile, or equivalent was found.
- **Fix:** Add protected CI with tests, linting, type/static checks, dependency scanning, secret scanning, SAST, container scanning, migration validation, staging deployment, approval, and rollback.

### F-017 — Dependency vulnerabilities

- **Category:** Dependencies
- **Severity:** HIGH
- **Evidence:** `npm audit --omit=dev --audit-level=moderate` reported **12 vulnerabilities**:
  - 1 critical
  - 2 high
  - 5 moderate
  - 4 low
- **Important packages affected:** Next.js, PostCSS, `mysql2`, `nanoid`, `qs`, `body-parser`, AI SDK transitive dependencies.
- **Fix:** Upgrade deliberately in a branch, run regression tests, verify Next.js compatibility, and avoid blindly using `npm audit fix --force`, which proposes a breaking Next.js major upgrade.

### F-018 — Production build failure

- **Category:** Release engineering
- **Severity:** HIGH
- **Evidence:** `npm run build` failed with `EPERM` opening `frontend/.next/trace`.
- **Fix:** Clean/recreate build output, identify file ownership/locking or antivirus interference, ensure CI uses a clean workspace, and make a successful production build a release gate.

- **Category:** Concurrency
- **Severity:** MEDIUM
- **Problem:** Concurrent write requests can overwrite each other because read-modify-write is not locked or transactional.

### F-025 — Missing timeout and circuit-breaker policies

- **Category:** Reliability
- **Severity:** MEDIUM
- **Problem:** External Gemini, B2, Redis and Frappe calls lack consistent timeout, cancellation, retry classification and circuit-breaking.

### F-026 — No pagination on several data access paths

- **Category:** Performance / Abuse
- **Severity:** MEDIUM
- **Locations:** course, progress, admin and Frappe data retrieval paths.
- **Problem:** Some queries and Redis key scans can grow without bound.
- **Fix:** Enforce pagination, maximum limits and cursor-based retrieval.

### F-027 — Error leakage

- **Category:** API security
- **Severity:** MEDIUM

  - `frontend/app/api/categories/route.js`
  - several route handlers

### F-028 — Prompt injection controls are inadequate

- **Category:** AI security
- **Severity:** MEDIUM
- **Problem:** Keyword filtering in `queue_worker.py` is not a security boundary. Retrieved documents and user content are inserted into system/context prompts without strong content isolation.
- **Fix:** Treat documents and user content as untrusted. Separate instructions from data, validate tool calls, constrain output, apply tenant-aware retrieval, and test indirect prompt injection.

5. Business logic embedded in route handlers
6. Inconsistent authorization implementations

## Recommended target architecture

- Make Frappe or a dedicated API layer the authoritative business-data service.

- Move document ingestion to a separately deployable worker.
- Use a durable queue.
- Keep B2 private and access-controlled.
- Use Redis only for cache, rate limiting and ephemeral state.
- Remove all silent demo fallbacks in production.

# 21. 🚨 MUST FIX BEFORE PRODUCTION

## 1. Close all authorization gaps

- **Evidence:** Unauthenticated writes in course, assignment, quiz, category and syllabus APIs; unauthenticated progress/memory access.
- **Risk:** Full data tampering and cross-user disclosure.
- **Exact fix:** Add centralized `requireUser` and `requireRole` middleware. Derive identity from a server-controlled session. Require explicit admin permissions for all mutations.
- **Verification test:** Anonymous requests return `401`; student requests to admin APIs return `403`; User A cannot access User B’s data after modifying all IDs.

## 2. Remove hardcoded credentials and fallback secrets

- **Evidence:** Fixed passwords and hardcoded JWT/encryption fallback.
- **Risk:** Immediate account takeover.
- **Exact fix:** Rotate all exposed secrets; remove fallback values; remove demo credentials from UI; implement secure bootstrap and forced password reset.
- **Verification test:** Application fails closed when secrets are missing; forged JWTs are rejected; old credentials no longer work.

## 3. Re-enable CSRF protection

- **Evidence:** `ignore_csrf 1`.
- **Risk:** Cross-site authenticated mutations.
- **Exact fix:** Re-enable CSRF, implement origin validation and secure cookie policy.
- **Verification test:** Cross-origin mutation without valid CSRF token is rejected.

## 4. Remove PII and secrets from repository/workspace distribution

- **Evidence:** PII in `backup.sql`, secrets in `.env` files.
- **Risk:** Privacy breach and credential compromise.
- **Exact fix:** Revoke/rotate secrets; remove database dump or replace with anonymized fixtures; audit history and backups.
- **Verification test:** Secret scanner returns no active credentials; sanitized dump contains no real personal data.

## 5. Remove destructive production initialization

- **Evidence:** Startup script drops all tables when initialization check fails.
- **Risk:** Catastrophic data loss.
- **Exact fix:** Separate provisioning, migration and startup. Require explicit development-only destructive flag.
- **Verification test:** Simulated transient DB failure never triggers table deletion.

## 6. Implement AI and upload abuse controls

- **Evidence:** Public AI endpoints and partial upload rate limiting.
- **Risk:** API key compromise, cost explosion and denial of service.
- **Exact fix:** Authentication, per-user/IP/global limits, request size limits, token ceilings, concurrency caps, timeouts and spend alerts.
- **Verification test:** Quotas enforce `429`, limits cannot be bypassed by changing user IDs or headers.

## 7. Resolve dependency and build failures

- **Evidence:** 12 npm audit vulnerabilities and failed `npm run build`.
- **Risk:** Known vulnerabilities and inability to produce a reliable release.
- **Exact fix:** Upgrade compatible versions, test, lock versions, and resolve `.next/trace` filesystem issue.
- **Verification test:** Clean checkout passes install, audit policy, lint, tests and production build.

## 8. Establish backups, restore and rollback

- **Evidence:** No restore test, rollback procedure or RPO/RTO documentation.
- **Risk:** Irrecoverable data loss or prolonged outage.
- **Exact fix:** Encrypted scheduled backups, off-site retention, restore automation, migration rollback plan and documented runbook.
- **Verification test:** Restore into isolated environment and execute critical user flows.
